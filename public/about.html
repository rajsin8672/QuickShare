About F Share

F Share was engineered from the ground up to solve a universal friction point: transferring documents, pictures, videos, and notes between disparate devices, operating systems, and users without requiring user registration, email invitations, or permanent storage footprints.

Technical Architecture

F Share employs a modern, lightweight, and decoupled architecture separating frontend presentation, backend REST services, database state, and object storage:

  • Frontend: Clean Vanilla HTML5, CSS3, and JavaScript utilizing the Fetch API, semantic markup, and responsive design systems. Fast page loads with zero heavyweight frameworks.
  • Backend Engine: Node.js and Express.js REST API service configured with Helmet security headers, Multer streaming uploads, and multi-tier rate limiting defenses.
  • Database Tier: Supabase PostgreSQL with strict Row Level Security (RLS) enforcing backend service-role access only.
  • Object Storage: Supabase Storage with dedicated private bucket shared-files. Public access is disabled at the storage engine level.

Security & Privacy Model

Unambiguous Code Alphabet

Generated codes utilize a custom 32-character base that excludes visually confounding characters (such as 0 vs O, 1 vs I or l), preventing transcription errors across devices.

Bcrypt Password Hashing

Optional share passwords are cryptographic hashes salted with bcrypt. Plaintext passwords are never written to the database or logged in server telemetry.

Zero Permanent Storage Footprint

An automated, scheduled cleanup service scans for expired shares and permanently purges underlying files from storage and records from the database.

Brute-Force Shield

Strict IP-based rate limiting on code verification and download endpoints throttles repeated attempts and prevents dictionary or guessing attacks.
